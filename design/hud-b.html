The waiting orb — how much room does it need?

At the reference size the orb is ~1,200 dots whose radius is about 1/136th of the sphere. Scale that down to a 28 px orb and every dot is 0.2 px — it stops being an orb and becomes a smudge. So the real question is not what the orb looks like, it is where it is allowed to be big enough. All four below are live, drawn with the same maths, at true size.

The reference defaults to SwiftUI .mint. The rest of the waiting state in this app is orange. Mint keeps the orb recognisably “the Waveform thing”; orange keeps the app internally consistent.

What I’d build

Option 3 — a 44 px orb in a pill that grows to 172 × 56 while waiting. It is the smallest amount of extra room that lets the orb be the real thing rather than a dot-smudge, it keeps B’s “one small object” character, and it does not grow the way the “Heard nothing” state does, so the two growth cases stay distinguishable: taller means busy, wider means it needs you.

On colour I would go mint. The orb is a borrowed object with its own identity, and mint reads as “audio is being computed here” rather than repeating the orange that already means “working” elsewhere in the app. Timer slot: ellipsis when the pill stays tight, the word when it is wide.

One honest caveat about the waiting orb: the model’s own rule is that nothing is invented, so a sphere with no audio is just a plain turning sphere. If you want it to pulse while waiting, that has to be a decision — it is no longer showing data.
