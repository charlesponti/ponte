Ponte · why a mic picker needs a new capture path

Issue #19 · the left column is what the code does today; the right is the seam the spike proved out.

The problem, in one line

  • • An AVAudioEngine builds its graph the first moment you touch inputNode.
  • • Setting the device afterwards is accepted — the hardware switches — but the graph keeps the old format.
  • • The tap is then created with the new format and AVFAudio aborts.
  • • It is an Objective-C exception, so Swift cannot catch it. The only safe move is not to try.

What the spike proved

  • • A chosen AVCaptureDevice records with no graph to repoint.
  • • audioSettings gives 16 kHz mono 16-bit directly — no converter.
  • • 3.023625 s of audio from a non-default device, valid WAV, 96 756 bytes.
  • • Five traps documented so the real build doesn't rediscover them.

The plan

  • • AudioSource seam: start(onBuffer:) · stop().
  • • EngineSource = today's path, so Thames is untouched.
  • • CaptureSource = session + device UID.
  • • Then #14's picker has something real to write to.
