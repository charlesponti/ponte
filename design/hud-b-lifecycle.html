The 64 px orb — a lifecycle, not a spinner

One orb, four behaviours: recording spins fast and mint, working holds mint at the model’s own calm rate, done turns green and shrinks away, error shrinks, turns red and throbs three times. Same 64 px orb, 1,100 dots, inside the 96 px squircle.

Done — keyframes

The colour change lands first and is held for 150 ms, so it registers before anything moves. Then it shrinks and fades over 700 ms. Dot count falls with the scale — 1,100 → ~330 — so the dots keep resolving instead of clotting, which is the same rule that made 44 px the smallest legible sphere.

Error — keyframes

Turns red in 180 ms and shrinks to 82% — it does not shrink away, because it has something to say. Then three throbs at 420 ms apart: the object scales 1.00 → 1.12 → 1.00, the dots do not push out. Pushing dots out would mean loudness in this model, and inventing loudness here would be a lie about the audio.

Spin direction and continuity. The sphere keeps turning through every transition rather than resetting — it decelerates into done and error instead of stopping dead, so the object reads as one continuous thing that changed mood, not four different spinners.

Two things I had to decide for you, both changeable: whether “working” keeps spinning fast (I read your sentence as only recording being fast, so working drops to the model’s calm 0.35 — the tweak above lets you pick eager instead), and whether the orb is the only thing that shrinks (I’ve kept it that way: the squircle stays put and only the orb shrinks and leaves, so the HUD’s footprint never jumps during a transition).
